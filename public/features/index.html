01 · The agentic workflow

Plans before it builds, then keeps going

A chat box that dumps files is not a product team. AIWA works the way a real one does: scope the brief, design the solution, write the stack, drive the app in a browser, publish it, and come back to the same codebase tomorrow.

  • Turns a sentence into a scoped brief, with entities named before files
  • Schema, routes and state decided up front, not discovered mid-build
  • Full stack: UI, API, database, auth and jobs, streaming to a live preview
  • Tests the flows a user would click, then publishes only what passed

02 · Project Brain™

Change twelve behaves like change one

AIWA keeps a persistent record of the product: pages, data, design decisions and the reasons they were made. A prompt in month six is fitted to the app that exists, rather than regenerated around it.

  • New features land on the architecture you already approved
  • Correct a decision once and later work respects the correction
  • Version history on every build, with restore when a change goes wrong
  • Explore the codebase in conversation before you ask it to move

03 · Managed backend

A working app, not a painted prototype

If the product needs users, records and rules, AIWA provisions them with the interface. Each project can get Neon Postgres, Google or email sign-in, row-level access, and the APIs the screens actually call. You describe what people should be able to do.

  • Postgres per project, schema described in plain language instead of SQL
  • Google and email/password auth, with protected areas and roles
  • Server-side logic for the actions that must not live only in the browser
  • Infrastructure only where the product needs it. A portfolio can stay a site

How you work

Four modes, because building is not one kind of thinking

Mode tells AIWA how to approach the request. You can switch at any time. There is no penalty for changing your mind.

Build

Create or change something. Pages, features, design, connectors, behavior. The mode you will live in once you know what you want.

Plan

Think before it writes. Requirements, flows, data, permissions and the risks, as a spec you can approve or send back.

Explore

Understand the product without moving it. How auth works today, what a team workspace would take, where onboarding stalls.

Debug

Find the cause, then fix it. Runtime errors, failed requests, auth loops, integration faults, with the reproduction you can give it.

Integrations

Connectors, with your keys

Payments, email, SMS, media, calendars and the model behind an in-app assistant. You connect the account. AIWA writes the code that uses it, live in the preview and on the published URL.

  • Stripe Checkout, subscriptions, upgrades, downgrades, gated features from real plan state.
  • Resend Welcome, booking, order, invitation and status mail from your own sending domain.
  • Twilio SMS confirmations, reminders and alerts fired by events inside the app.
  • Cloudinary Upload, transform and deliver images and other media the product stores.
  • OpenAI Assistants, generation, summarization, classification and extraction in the app you ship.
  • Anthropic Claude for document analysis, extraction, drafting and heavier reasoning features.
  • Google Gemini Assistants, generation, extraction and multimodal features on Gemini.
  • xAI Grok Generation, extraction and analysis with Grok inside the same connector model.
  • Calendly Demo, consultation and onboarding scheduling in the customer workflow.
  • Google Calendar Create, update and cancel events from bookings, appointments and CRM activity.
  • Google Meet Meeting links for bookings, demos, consultations and virtual appointments.
  • Google Drive Bring project files and shared resources into the workflows the app runs.
